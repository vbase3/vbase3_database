# Cross-Reference System

## Overview

Different immunoglobulin gene databases use different naming conventions. DNAPLOT provides a cross-reference system to translate gene names between databases.

## Supported Databases

### VBASE2
- **Format**: Species prefix + gene type + family + number
- **Examples**: 
  - `musIGHV115` (mouse heavy chain V-gene)
  - `humIGKV134` (human kappa V-gene)
- **Characteristics**: Internal numbering, compact

### IMGT
- **Format**: Standard nomenclature with gene/allele
- **Examples**:
  - `IGHV1-18*01` (heavy chain V-gene, family 1, gene 18, allele 01)
  - `IGKV1-5*01` (kappa V-gene)
- **Characteristics**: Official nomenclature, includes allele information

### OGRDB
- **Format**: Open Germline Receptor Database names
- **Examples**: May vary by species and submission
- **Characteristics**: Community-curated, may have novel alleles

## Data Structures

### CrossReference

```rust
pub struct CrossReference {
    pub vbase2_to_imgt: HashMap<String, String>,
    pub imgt_to_vbase2: HashMap<String, String>,
    pub vbase2_to_ogrdb: HashMap<String, String>,
    pub ogrdb_to_vbase2: HashMap<String, String>,
    pub gene_type: GeneType,  // V, D, or J
    pub species: Species,      // Human, Mouse, etc.
}
```

### AllNames

```rust
pub struct AllNames {
    pub human_v: CrossReference,
    pub human_d: CrossReference,
    pub human_j: CrossReference,
    pub mouse_v: CrossReference,
    pub mouse_d: CrossReference,
    pub mouse_j: CrossReference,
}
```

## Source Files

### VBASE2 ↔ IMGT Mappings

Located in `data/vbase2/database/`:
- `VBASE2_IMGTnames.table` - V-gene mappings
- `VBASE2_IMGTnamesDJ.table` - D and J segment mappings

Format:
```
musIGHV001	IGHV1-18*01
musIGHV002	IGHV1-18*02
humIGKV134	IGKV1-5*01
...
```

### VBASE2 ↔ OGRDB Mappings

Generated by `scripts/generate_ogrdb_mappings.py`:
- Compares sequences between databases
- Creates mappings where sequences match
- Output: `VBASE2_OGRDBnames.table`

## Translation Functions

### Basic Translation

```rust
pub fn translate_v_gene(
    name: &str,
    from: Database,
    to: Database,
    species: Species,
    all_names: &AllNames,
) -> String {
    if from == to {
        return name.to_string();
    }
    
    let cross_ref = match species {
        Species::Mouse => &all_names.mouse_v,
        Species::Human => &all_names.human_v,
        _ => return name.to_string(),
    };
    
    match (from, to) {
        (Database::Vbase2, Database::Imgt) => {
            cross_ref.vbase2_to_imgt.get(name)
                .cloned()
                .unwrap_or_else(|| name.to_string())
        }
        (Database::Imgt, Database::Vbase2) => {
            cross_ref.imgt_to_vbase2.get(name)
                .cloned()
                .unwrap_or_else(|| name.to_string())
        }
        // ... other combinations
        _ => name.to_string()
    }
}
```

### Automatic Species Detection

```rust
pub fn determine_species_from_v_gene_name(name: &str) -> Species {
    let name_lower = name.to_lowercase();
    
    if name_lower.starts_with("mus") || name_lower.starts_with("mouse") {
        Species::Mouse
    } else if name_lower.starts_with("hum") || name_lower.starts_with("human") {
        Species::Human
    } else if name_lower.contains("ighv") || name_lower.contains("igkv") {
        // IMGT format - need to check context or default to human
        Species::Human
    } else {
        Species::Other
    }
}
```

## Usage Examples

### CLI

```bash
# Output in IMGT format
dnaplot vbase2 analyse -i seq.fasta --name-format imgt -o output.html

# Output in VBASE2 format (default)
dnaplot vbase2 analyse -i seq.fasta -o output.html
```

### Python

```python
import dnaplot

# Analysis returns VBASE2 names by default
result = dnaplot.analyze(sequence, "test", "mouse", "H")
print(result.v_gene)  # "musIGHV115"

# Get HTML with IMGT names
html = dnaplot.get_imgt_html(sequence, "test", "mouse", "H", name_format="imgt")
# V-gene shown as "IGHV1-18*01"
```

### Rust

```rust
use dnaplot_lib::{translate_v_gene, Database, Species};

let vbase2_name = "musIGHV115";
let imgt_name = translate_v_gene(
    vbase2_name,
    Database::Vbase2,
    Database::Imgt,
    Species::Mouse,
    &all_names,
);
assert_eq!(imgt_name, "IGHV1-18*01");
```

## Adding New Mappings

### Manual Addition

Edit the appropriate `.table` file:
```
# In VBASE2_IMGTnames.table
newVGENE001	IGHV1-NEW*01
```

### Sequence-Based Mapping

Use the mapping script:
```bash
cd scripts
python generate_ogrdb_mappings.py \
    --vbase2-dir ../data/vbase2/database \
    --ogrdb-dir ../data/ogrdb \
    --output ../data/vbase2/database/VBASE2_OGRDBnames.table
```

The script:
1. Loads sequences from both databases
2. Compares sequences (exact match)
3. Creates mappings where sequences are identical
4. Generates coverage report

## Handling Missing Mappings

When a mapping doesn't exist:
1. Return the original name unchanged
2. Log a warning (in debug mode)
3. Consider adding the mapping to the table

Common reasons for missing mappings:
- Novel allele not in both databases
- Naming convention differences
- Pseudogenes or ORFs
